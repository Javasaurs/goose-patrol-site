User requirements

Priority: shall (essential), should (important), may (optional).

IDDescriptionPriority
UR_PLAYERThe game allows the user to control a player character.Shall
UR_SCOREThe system should give the user a score at the end of the game.Shall
UR_MAPThe game should display a map of the university.Shall
UR_ITEMSThe game allows the user's player character to use items.Shall
UR_EVENTSThe game should have hidden events.Shall
UR_TIMERThe game will time how long the player takes to beat the game.Shall
UR_GEESEThe game will feature geese that disrupt the player.Shall
UR_UXThe game will offer a pleasant user experience.Should
UR_TARGET_AUDIENCEThe game will be suitable for current undergraduate students.Should
UR_ACCESSIBILITYThe system should support a variety of users.May
UR_SOUNDThe system will have sound effects and music.May

Functional requirements

IDDescriptionUser requirement
FR_PLAYER_MOVEMENTThe system will allow the user to make the player character move.UR_PLAYER
FR_PLAYER_USE_ITEMThe system will allow the user to make the player use items.UR_PLAYER
FR_PAUSEThe system will allow the user to pause the game.UR_UX
FR_GEESE_SPAWNINGThe game will frequently spawn geese.UR_GEESE
FR_GEESE_VARIETYMake geese different sizes, strengths and speeds.UR_GEESE
FR_MUSICMusic will play during the game.UR_SOUND
FR_GEESE_SFXThe geese will quack and make different sound effects.UR_SOUND
FR_ITEM_SFXDifferent sound effects will play when the player uses an item.UR_SOUND
FR_EVENT_TRIGGERSThe game will trigger hidden events.UR_EVENTS
FR_TIME_OUTThe game will end if the 5 minute timer runs out.UR_TIMER
FR_DISPLAY_TIMEThe game will continuously display the timer, and update as it changes.UR_TIMER

Quality requirements

IDDescriptionUser requirementFit criteria
QR_COLOUR_BLINDNESSThe game will be colour-blind friendly.UR_ACCESSIBILITYAll colours used come from a colour-blind friendly palette.
QR_CONTROLSThe controls will be simple and easy to understand.UR_UXIntuitive buttons for different player actions.
QR_SCORE_ITEMSThe player's use of items should affect scoring.UR_SCOREUsing items deducts score if used badly or improves it if used smartly.
QR_SCORE_EVENTSThe player's handling of hidden events should affect scoring.UR_SCOREAll hidden events must alter the player's score.
QR_SCORE_TIMEHow quickly the player beats the game should affect the score.UR_SCOREReduce the player's score by 1 every second.
QR_MAP_VISUALSThe map should resemble qualities of the university.UR_MAPThe map has at least 2 buildings, a lake and grass.
QR_MAP_MOVESThe map should move with the player (either camera or map moves on screen).UR_MAPCamera moves with the player, and the player is centred on screen.
QR_PLATFORMThe game should run on desktops and laptops.UR_TARGET_AUDIENCEThe game is runnable on desktops and laptops.
QR_DIFFICULTYThe game should be of medium difficulty.UR_UXGame is beatable within 2.5 minutes.
QR_STYLEThe game should be top-down view.UR_UXGame is displayed from a top-down facing 2D camera.
QR_EVENT_COUNTThe game should feature hidden events.UR_EVENTSAt least 5 hidden events.
QR_INITIAL_ITEM_COUNTThe game should feature initial inventory items.UR_ITEMSAt least 5 initial inventory items.
QR_PICKUP_ITEM_COUNTThe game should feature multiple different pickup items (found on the map).UR_ITEMSAt least 5 pickup inventory items.
